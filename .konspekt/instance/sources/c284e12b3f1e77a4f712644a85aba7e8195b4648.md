**User:** I think it has to

**Claude:** "[…] **building it doesn't answer it.** TUF gives you the mechanism for rotation and compromise recovery; it says nothing about who holds root keys […]. **The hermeticity tension is real and has a clean resolution.** […] the TUF snapshot crosses the perimeter as a pinned, versioned file […]. Critically, **the `verdict` must record which trust-root version it verified against.** Otherwise 'a regulator can re-run this decision offline and get the same answer' is false the moment the registry changes. […] it's exactly `noteworthy-referent-binding` […]. **Revocation after admission is genuinely unmodeled.** […] does revocation force re-verification, or record an exposure? **Third instance of threshold signing.** […] *no single key is ever load-bearing; agreement is always threshold, never majority, dissent always disqualifying.*"

**User:** The trust keys are held by osera (alliance) with all member banks being...delegates? (Secondary owners, in case osera collapses or in case a bank deals with a vendor directly but through osera rails)

**Claude:** "[…] That's two different mechanisms, and TUF only calls one of them delegation […]. **Continuity is a root-threshold question, not a delegation one.** TUF delegation runs *downward* […]. A delegate can't sign a new root. So if OSERA solely holds the root keys and dissolves, delegation buys you nothing — and it's worse than 'no new artifacts,' because root metadata **expires**. When it lapses with nobody able to re-sign, every client hard-fails closed. Verification bricks. The fix is that member banks are **co-signers in the root threshold**, not delegates: root is k-of-m spanning the alliance *and* participating institutions. […] **Your second case is exactly what delegation is for.** A bank dealing with a vendor bilaterally gets a delegated targets role over its own scoped path. […] **But there's a trap in it worth naming now.** Under a bilateral delegation, the bank is issuer *and* consumer for that path — the maker/checker split collapses, and with it the k-of-n quorum property. […] **One thing that already works in your favour:** collapse doesn't invalidate history. […] does the delegated bilateral path stay **inside** the same admission policy […] or is it an explicitly weaker tier […]?"

**User:** Co-signing and delegation, fine. The 2nd line will be fine, as the banks bring open source in today without any of these guard rails

**Claude:** "[…] the counterfactual isn't a stricter regime, it's an unguarded one. I'd accept that argument for the conflict question. It doesn't quite dispose of the tiering question, though, and that one I'd resolve the other way: **no weaker tier.** […] If a bilateral artifact can't muster k-of-n independent verifiers, it fails the gate like anything else […]. A second tier is the kind of thing that's well-understood on the day it's created and load-bearing-but-forgotten three years later. What the bilateral path does need is **attribution, not leniency**: the `verdict` records which trust path admitted the artifact […]."
