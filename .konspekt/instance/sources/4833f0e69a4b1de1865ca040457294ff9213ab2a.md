**User:** Can we store the jar hashes centrally

**Claude:** "Yes — and it's a better answer than dual-publish, because it solves discovery without duplicating bytes. **It already has a name in the design: Archivista.** A central digest→attestation index is precisely what it does […]. So this isn't new machinery, it's **promoting Archivista from optional to load-bearing**, for a different reason than before. **The key property is that the index can be untrusted.** It's a lookup, not evidence. If it's wrong, compromised, or lying, you get pointed at the wrong attestation set — and you detect that immediately, because every attestation is signed, digest-bound, and checked against the contract. Nothing about admission rests on the index being honest. […] **And it's a projection, not an authority.** Every attestation is already logged in Rekor, so the index is rebuildable by replaying the log. […] It also answers the obvious objection that a central index is a censorship point: it can hide that an attestation exists, but the log can't, and the log is what you reconcile against. **Hermeticity is untouched** […]: the index is read at **resolution** time by ③, before the bundle is sealed. Resolution is online; *verification* is offline. The perimeter is the line, not the whole bank. […] **Artifact** — stays in the ecosystem-native repo […]. No duplicate bytes. […] One caveat rather than an objection: this **partially reverses** `noteworthy-bundle-format`, which concluded Archivista was optional. That conclusion was about *transport* […] and it still holds. This is about *resolution*, a different job."
